# 面试题归类（仅基于 城市生活 项目）

> **范围说明**：评估只看 城市生活 项目本身，不结合其他项目或实习经历。
>
> 标记说明：
> - ✅ = 城市生活 项目代码能直接支撑回答
> - 🧠 = 项目无对应实现，但属于通用八股，能凭知识回答（不能说"我项目这么用"）
> - ⚠️ = 可以答但有薄弱点，需要补充知识
> - ❌ = 城市生活 无法支撑（归入"无法解决"）
>
> **城市生活 实际使用的关键技术清单**（用于判定）：
> - Redis：**standalone 单机**（不是集群、不是主从）
> - 缓存：Caffeine + Redis 二级缓存、布隆过滤器、逻辑过期+空值缓存
> - 限流：自研 ZSet 滑动窗口（@SlidingWindowLimit AOP）
> - 锁：Redisson、SimpleRedisLock + Lua
> - 秒杀：Lua 脚本 + RocketMQ 异步下单
> - MQ：RocketMQ（含延迟消息），无 Kafka/RabbitMQ
> - GEO/Bitmap/ZSet/Set 全套 Redis 数据结构
> - 支付：支付宝 + 微信
> - AI：单 Agent（ReAct）+ Spring AI + Milvus 向量库 + MCP 协议 + SSE 流式
> - 数据库：MySQL（无 ES、无分库分表、无 binlog 监听）

## 五、薄弱点 & 短板小结

**Java 方向短板**（少量，集中在）：
- 本地缓存底层源码细节（Caffeine 的 W-TinyLFU 等）
- Counting Bloom Filter
- 削峰解耦后压测数据

**AI 方向短板**（集中在 RAG 工程化和高级特性）：
- RAG 召回质量评估指标
- 上下文压缩 / 异步摘要 / 关键信息提取
- 用户提示词指代消解
- MCP 网关、消息可靠性
- Bad case 和幻觉处理

**完全不具备的能力**：
- Multi-Agent（主子 Agent、任务池）
- LoRA 微调 / 自部署模型
- PDF/Markdown 文档解析与切片
- 图像类（以图搜图、AI 扩图）
- ES + binlog + Mycat 一类的传统大数据/分库分表
- 敏感词 DFA / AI 审核
